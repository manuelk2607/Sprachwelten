# Sprachwelten

Sprachwelten is a separate application. Do not copy or alter code from sibling projects.

Primary production is the owner’s Cloudflare Worker `sprachwelten`: https://sprachwelten.maki26.workers.dev. Publish updates with `npm run deploy:cloudflare` after building. The `.openai/hosting.json` ID refers to the earlier, separate Sites publication; do not deploy there unless the user asks. Preserve existing server secrets and the current Neon database/auth project.

- Write all owned application code, configuration and Node scripts in TypeScript (`.ts`, `.tsx`, `.mts`). Do not introduce `.js` or `.mjs` source files. Dependencies and generated bundles are outside this rule.
- Maintain German and English UI together. Keep original expressions unchanged. Use canonical quiz category IDs and separately stored DE/EN explanations. Cloudflare Workers AI suggestions use the server AI binding, signed-in access, rate limits and a review before publication; never translate during game polling.
- Twelve current variants are grouped into eight UI families. The default meaning quiz merges idioms/dialects, Gaming, youth language and academic language; all players directly select a meaning, with one point per correct answer. Four legacy bluff/cooperative mode IDs remain compatible with saved rooms but are absent from the new start menu. Quizzes, word building and word chains allow 1–10 players; tongue twisters require 2–10 for peer ratings. Tongue twisters use live speech in the same room or voice chat; scores are provided by the other players.
- Correct answers award one point in quizzes and the bluff game; a successful bluff adds one point per fooled player. Tongue-twister peer ratings remain 1–5.
- Preserve database-enforced contribution uniqueness from migration 006, including concurrent requests. Match kind, original language and normalized phrase, plus region for dialects or context for situations. Direct contributors to existing entries for additional explanations.
- Round count is host-configurable from 1 to 10, also limited by unplayed unique prompts. Same-room rematches can return to the lobby to configure the whole game, category and rounds, or restart immediately with the same settings in one atomic mutation. Insufficient unplayed cards must not erase the final result or silently shorten an immediate rematch. Keep category and round count side by side, aligned with the game selector's right edge; without a category, align the round count left. Persist private played-prompt history across matches, games and category changes; never silently recycle exhausted prompts. Preserve confirmed leave, earliest-remaining-player host transfer and reconciliation of unfinished turns.
- Keep the IANA language allowlist and search registry synchronized. Optional credit names never override account identity. Audio is opt-in, max 20 seconds, server-validated canonical WAV in the private AUDIO R2 binding; only attached clips are public.
- Keep author identity and permissions on the server. Use the managed Neon Auth SDK for email/password authentication.
- New text/audio contributions and community regions allow guests. Derive guest author/audio ownership from an opaque HttpOnly, SameSite cookie with a separate `guest:` ID namespace, never request author fields or a shared guest ID. Preserve origin validation, per-identity limits plus hashed IP limits for guests, and private audio isolation. Own management, suggestions, AI translations and administration still require managed account sessions; never auto-claim guest entries by name or email. Explain these optional account benefits in DE/EN.
- Keep SQL migrations under `db/migrations/`. Run the tracked migration runner; never put credentials in source.
- Keep answers, author assignments and future cards out of room responses until their reveal phase. Preserve optimistic concurrency checks.
- Attendance lives in `room_presence`; routine heartbeats must not rewrite or version the game. Merge private presence before stale-player reconciliation. Scheduled maintenance removes expired rooms and old limits in bounded batches. Pronunciation actions require the current match ID, round and speaker.
- Round availability is scoped to the chosen category and constrains lobby choices. Preserve separate meanings, languages and dialect regions when selecting unique cards. Never use another valid meaning of the same expression as an automatic wrong answer.
- Validate with `npm run typecheck`, `npm test` and `npm run build`. Use `npm run test:integration` with `.env.test.local` and a configured isolated test database and running server when changing auth, persistence or the game API.

- Zungenbrecher has the Zungenknoten and Klangfallen categories; both repeat a supplied sentence and use peer ratings. Quote rooms distinguish person quotes from song titles. Word building accepts only stored sequences and randomizes public tile IDs per round. Cooperative tasks keep their source briefing and targets private to the caller until reveal.

- Contributions explicitly select `presentation` as text, audio or both. Audio-only entries have an empty phrase and require owned audio with a server-computed hash. Preserve partial text uniqueness and the audio-content identity index. Do not collapse empty audio transcripts into one game prompt or disclose unselected media in room projections. Legacy rounds without presentation infer both when audioId exists.
- Audio recordings and files are previewed and trimmed locally before upload. Source files are limited to 20 MB and 5 minutes; the final canonical WAV clip remains at most 20 seconds. Pending edits block contribution submission; cancelling preserves the previously attached clip. Own-contribution search is session-scoped on the server, includes translations and uses literal wildcard escaping before pagination.

- Public attribution uses only explicit credit names; never fall back to account names, including explanations and game reveals. Keep internal author metadata available only to administration.
- Plain language contributions require a literal translation and accept an optional explanation. Structured meaning cards instead require one correct and three distinct wrong answers, with no duplicated mandatory explanation. The editor shows the correct answer first while preserving legacy stored correctIndex values. Games independently shuffle answers every round. Keep legacy stored cards valid and withhold solutions before reveal. Discovery starts closed and lists answer-free previews only.
- Starter idioms and dialects use bilingual expression-specific distractors only while their original meaning is unchanged. Authored choices remain authoritative. Automatic fallback choices prefer the same content kind and similar wording/length and exclude other valid senses of the same expression; random answer placement does not establish distractor quality.
- All administration endpoints must check the managed session and `app_admins` on the server. Keep grants tied to an existing immutable account ID. Preserve ownership, revision checks, uniqueness, moderation audit and recoverable removals. Never expose credentials/session tokens in user lists or grant synthetic test accounts access without explicit authorization.

- Keep old mode IDs and stored rounds compatible. New meaning contributions use meaning challenges; legacy relay/academic cards are adapted for meaning quizzes without mutating their stored data. The joke quiz has four distinct bilingual interpretations and scores one point. Word chains use checked German/English decks and server-enforced turns, word IDs, match IDs and no-repeat rules. Loanword cards explicitly record the immediate donor language. Outsider cards store a bilingual rule, four choices and an explanation.
- Own edits/deletions require immutable author ID and revision checks on the server. Foreign edits are pending `entry_suggestions`; acceptance and content mutation commit together. Admin bulk edits are all-or-nothing, max 30 entries. Preserve the moderation audit and private pending audio.
- Optional `sense` separates explicitly named meanings in text/audio uniqueness. New region IDs must resolve in `content_regions`; community region names are not certified geographic data. Keep solutions out of previews and hidden game phases.
